# 로그인 계정별 AI 연결

## 동작

- 현재 관리자 로그인 식별자 `agency_accounts.institution_code`당 설정 1개를 저장합니다. 기관명이나 역할명이 아닌 로그인 식별자를 사용합니다.
- 통합관리자·그룹관리자·운영담당자 모두 본인 설정만 관리합니다. 상위 계정 설정을 상속하지 않습니다.
- 텍스트 설문 초안, 파일 초안, 분석 추천, 분석 보고서는 같은 설정을 조회합니다. 설문 생성 등 기존 업무 권한은 변경하지 않습니다.
- 미설정/중지 상태는 화면에서 차단하고 서버에서도 거부합니다. Netlify 공용 키나 기본 모델로 대체하지 않습니다.
- OpenAI, Anthropic Claude, Google Gemini의 키로 모델 목록을 조회합니다. 지원 가능한 텍스트 모델만 노출하고 활성화 저장 시 선택 모델의 JSON 응답을 실제 검증합니다. 연결 확인·검증에는 제공자 사용 제한 및 소액 비용이 발생할 수 있습니다.
- 초기 파일 입력 지원은 OpenAI입니다. Claude/Gemini는 텍스트 생성·추천·참고파일 없는 분석을 지원합니다.
- 중지는 암호화된 키를 보존하며 재활성화 시 검증합니다. 키 삭제 후 저장하면 DB의 현재 키가 제거됩니다. 기존 설문·제출·분석 결과는 삭제하지 않습니다.

## 운영 반영 전 필수 사항 (별도 승인 필요)

1. 기존 DB 백업 및 `supabase/account-ai.sql` 검토 후 적용. 기존 스키마의 `agency_accounts`가 먼저 있어야 합니다. 이 파일은 스키마 원본이며 CLI 마이그레이션 이력이 아닙니다.
2. 서버 전용 `AI_SETTINGS_ENCRYPTION_KEY`에 암호학적으로 무작위인 32바이트의 base64 값을 설정합니다. 로그인 서명 키/API 키와 재사용하지 않습니다. 브라우저 번들 및 Git에 넣지 않습니다.
3. 코드 배포 후 각 사용자가 직접 키를 등록합니다. 공용 키를 사용자 설정으로 자동 복사하지 않습니다.
4. 실제 키로 모델별 소규모 설문 생성 및 분석을 검증합니다. 로컬 자동 검사는 합성 응답을 사용하므로 실제 제공자 호환성·요금·접근 권한까지 보증하지 않습니다.

암호화 키는 기존 저장 키를 복호화하는 데 필요합니다. 임의 교체하면 기존 연결을 사용할 수 없습니다. 교체 시 별도 재암호화 절차 또는 사용자 키 재등록 계획이 필요합니다. DB 백업에는 과거 암호문이 남을 수 있으며 제공자 키 폐기는 제공자 콘솔에서 수행합니다.

## 보안 및 동시성

- AES-256-GCM, 매번 새 IV, 로그인 식별자와 용도에 묶인 인증 데이터를 사용합니다.
- 브라우저에는 마스킹과 메타데이터만 반환합니다. 검증 직후에는 10분 만료의 계정 전용 암호화 증명을 전달하고 저장 시 다시 검증합니다. 키 원문은 검증 입력 이후 입력창에서 지웁니다.
- 모든 서버 작업은 서명된 로그인 토큰으로 소유자를 결정하고 계정 및 기관 활성 여부를 재확인합니다. 요청 본문으로 다른 계정을 지정할 수 없습니다.
- 테이블 RLS 활성화, anon/authenticated 직접 접근 및 RPC 실행 금지, 서버 service_role만 허용합니다.
- revision과 DB 원자적 저장으로 여러 창의 오래된 설정 덮어쓰기를 차단합니다. 연결 확인 및 활성화 검증은 계정당 분당 5회로 제한합니다.
- 고정된 제공자 HTTPS 호스트만 호출하며 외부 오류에서 키·응답 원문을 노출하지 않습니다. 자동 재시도/다른 AI로의 대체는 하지 않습니다.
