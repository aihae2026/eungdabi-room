# 설문 결과 분석 기능 설계 (v3)

제출된 설문 결과를 **집계 표(교차표) 중심의 기본 통계**로 보여 주고, 선택적으로 참고
자료를 근거로 한 구조화 분석(JSON)을 제공하는 기능이다.

- 범위: **점수·척도형 설문의 수치 통계**. 자유서술형 분석·개인 명단은 다루지 않는다.
- 계산은 코드가 수행한다. **STEP 2 추천은 규칙으로 만든다. AI는 사용자가 원할 때 받는 추가 추천
  (STEP 2 `AI에게 추천 더 받기`)과 결과 분석(STEP 4)에만 쓴다.**
- 진입점: **[집계 및 통계] 안의 `AI 통계` 탭**. `index.html` 의 `.stats-tabs` 에
  `data-stats-tab="ai"` 버튼을, `.v8-stats-results` 안에 `#v8Analysis` 화면을 둔다.
  기존 `제출 현황` 탭(옛 이름 `기관 참여 현황`)의 동작은 건드리지 않는다.
  (옛 `설문 응답 결과` 탭은 2026-09-14 화면에서 삭제했다. 서버의 `/stats?view=distribution`
  응답은 테스트가 검사하고 있어 남겨 두었다.)
- **조회 조건은 [집계 및 통계] 위쪽 패널 하나만 쓴다.** 세 탭이 같은 패널을 그대로
  공유한다. 설문 양식 · 기간 · 운영담당자 범위를 거기서 가져오고, **처리 상태**(전체 / 확인
  완료 건만)도 같은 패널에 함께 둔다.
  조회 조건이 바뀌면 분석 결과는 STEP 1로 초기화된다.
- ⚠️ **처리 상태는 지금 `AI 통계` 탭에만 효력이 있다.** `제출 현황`
  은 DB 함수 `admin_submission_stats` 가 집계하는데 그 함수가 처리 상태를 조건으로 받지
  않기 때문이다. 오해하지 않도록 필드 이름을 `처리 상태 (AI 통계 전용)` 로 쓰고 패널
  아래에 안내문(`#statsStatusNote`)을 둔다. 세 탭 모두에 적용하려면 그 함수에
  `p_status` 를 추가해야 하며, **운영 DB 변경이라 소유자 승인이 필요하다**(미착수).
- 화면은 **STEP 1 → 2 → 3 → 4 마법사**다. 위쪽 단계 표시줄로 오갈 수 있고, STEP 1을
  마치기 전에는 2~4로 넘어갈 수 없다.
- `AI 통계` 탭은 `/stats` 집계를 호출하지 않는다. `조건 적용` 버튼은 조건만 반영하고,
  실제 실행은 STEP 1 의 `다음` 버튼에서 `POST /analysis/run` 으로 한다.
- 권한: 기존 서명 토큰 그대로 (수행기관=자기 제출건 / 광역=관할 시도 / 중앙=전체).
- 출력: 화면 표 + CSV. 정식 서식 문서(PDF·docx)는 만들지 않는다.

## 자체 설문까지 집계 (2026-09-14)

자체 설문으로 받은 제출건은 `checklist_type` 이 비어 있고 `template_id` 로만 구분된다.
집계 DB 함수 `admin_submission_stats` 는 기본 3종(낙상·우울·기억)만 알아서, 예전에는
**자체 설문 제출건이 제출 건수에는 잡히고 확인 대기·완료에서는 빠졌다.** 운영 DB 함수는
고치지 않고 서버 코드에서 메운다.

- **설문 양식 선택지**: 기본 3종 + 운영 중·종료된 자체 설문(작성 중 제외). 모든 관리자
  권한이 `GET /stats/templates` 로 받는다. 값 형식은 `template:<양식 ID>`
  (`app.js` 의 `checklistTypeOf` 와 같다). 문항은 `GET /stats/templates/:id`.
- **제출 현황**
  - 설문을 고르지 않았을 때: 제출 건수·대상자 수·기본 3종 상태는 DB 함수 결과 그대로,
    **자체 설문 제출건만 직접 읽어** 상태를 더한다 → 행마다 `waiting_total`·`done_total`.
  - 기본 설문 하나를 골랐을 때: 자체 설문은 범위 밖이라 읽지 않는다.
  - 자체 설문 하나를 골랐을 때: DB 함수는 양식으로 거를 수 없어 그 양식 제출건만 읽어 기관별로 센다.
  - 자체 설문 제출건이 상한을 넘으면 결과를 몰래 빼지 않고 `templateStatusSkipped` 로 알린다.
  - 같은 `/stats` 를 쓰는 **조사 현황(홈)·기관 관리 목록의 확인 대기 수도 함께 맞게 된다.**
- **Supabase 1,000행 상한 대응** (`supabaseAllRows`)
  - PostgREST 는 한 번에 돌려주는 행 수에 상한(max-rows, Supabase 기본 1,000)이 있어
    `limit=20000` 을 줘도 **오류 없이 앞부분만** 온다. 예전 `POST /analysis/run` 이 그랬다.
  - 이제 `HEAD` + `Prefer: count=exact` 로 전체 개수를 먼저 받고 `order=id.asc&limit&offset` 으로
    끝까지 나눠 읽는다. 개수를 못 받으면 빈 페이지가 나올 때까지 읽는다.
  - 2만 건(`SUBMISSION_READ_LIMIT`)을 넘으면 틀린 숫자 대신 **413 "조건을 좁혀 주세요"** 로 멈춘다.
- **AI 통계에서 자체 설문**
  - `문항 응답별` 기준은 **선택형(단일·복수)만**. 서술형은 사람마다 문장이 달라 칸으로
    나눌 수 없고 개인정보가 섞일 수 있어 목록에서 빼고, 서버도 집계하지 않는다.
  - 선택형 응답은 `answer_value.labels`(보기 이름)로 읽는다. `answer_label` 에는 "기타:
    직접 쓴 내용"이 붙어 있어 쓰지 않는다 → **직접 입력 내용은 표·분포·추천 어디에도 나오지 않는다.**
  - 배점을 쓰지 않는 양식은 총점이 모두 0이라 `총점 구간` 대신 가장 두드러진 문항을 기준 축으로 추천한다.
  - 문항별 응답 분포의 대표 응답: 배점 있는 양식 = 배점이 가장 높은 보기, 배점 없는 양식 = 가장 많이 나온 응답.

### 복수 선택 문항 집계 규칙

한 사람이 여러 보기를 고르면 **보기마다 1씩** 센다 (`crosstab.js`).

| 값 | 뜻 |
| --- | --- |
| 칸 | 그 행 · 그 보기에 해당하는 사람 수 |
| 비율 | **행의 응답자 대비** — 복수 선택 열이면 한 행의 합이 100%를 넘을 수 있다 |
| 행 끝 `응답자 수` · 아래 `전체` | 칸의 합이 아니라 **사람 수(중복 없이)** |
| `rowMulti` / `colMulti` | 그 축에 실제로 여러 칸에 걸친 응답자가 있었는지 |

단일 선택만 있으면 결과는 예전과 완전히 같다(`합계` = 칸의 합, 비율 합 100%).

## 4단계 흐름

### STEP 1 · 분석 대상 설정
입력 칸을 따로 두지 않는다. 위쪽 **조회 조건** 패널에서 정한 설문지 · 분석 대상 기간 ·
운영담당자 범위(시도·시군구·운영담당자) · **처리 상태**를 **읽기 전용 요약**으로 보여 준다.
조회 조건 패널은 늘 펼쳐져 있으므로, 조건을 바꾸려면 위쪽 패널에서 바로 고친다.

- **처리 상태**(전체 / 확인 완료 건만) — "확인 완료 건만" = 대상자ID 입력·검토가
  끝난 제출건만 집계. 이 기능에만 쓰이므로 `AI 통계` 탭에서만 보인다.
- 설문 양식을 고르기 전에는 `다음` 버튼이 비활성이다. 분석은 설문 한 종류씩 진행한다.
- 운영담당자 범위 선택지는 기존 조회 조건 패널의 규칙을 그대로 따른다(권한 범위 안의 운영담당자만,
  운영담당자 계정에는 숨김).

### STEP 2 · 분석 기준 검토
- 상단에 데이터 자동 점검을 **최소한만** 표시: 응답 수(확인 완료/대기 분리) · 문항 구조 ·
  확인 필요 항목(생년월일 이상치, 미해당 처리).
- **집계 방식을 여러 개 추천**한다. 각 추천에 근거를 붙인다.
- 추천은 고정 목록이 아니다. STEP 1 조건으로 데이터를 **먼저 한 번 읽고**(요약 + 문항별
  응답률), 그 결과와 선택한 설문 양식의 문항·위험 구간을 함께 보고 만든다.
  - 총점 구간의 기본 경계값 = 그 설문의 **위험 구간**(예: 낙상 `26,60` = 저/중/고위험).
    정해진 위험 구간이 없는 양식(자체 설문)은 관측된 총점 범위를 3등분한다.
    배점을 쓰지 않는 자체 설문에는 총점 구간 추천을 만들지 않는다.
  - **위험 구간이 아닌 총점 구간은 "참고 구간"으로 밝힌다** (2026-09-14). 자체 설문의 3등분이나
    경계값을 바꾼 구간은 검증된 위험 기준이 아니므로, 추천 근거와 STEP 3 표 위에
    *"총점 구간은 점수 범위를 나눈 참고 구간입니다 (검증된 위험 기준 아님)."* 를 붙이고,
    STEP 4 AI 에도 참고 구간이라 알려 위험 수준으로 해석하지 않게 한다.
  - 문항 기준은 **대표 응답률이 높은 실제 문항**을 고른다(설문마다 다른 문항이 뽑힌다).
    대표 응답은 위험·해당을 뜻하는 쪽 보기다 — 빈도형 척도에서 "없음"이 가장 많아도
    그것을 대표로 삼지 않는다.
  - 쓸모없는 기준은 아예 빼 준다: 운영담당자가 1개이면 `운영담당자별`, 성별 기록이 없으면 `성별`,
    한 달치 데이터면 `조사 월` 추천을 만들지 않는다. **이 조건에서 응답이 한 가지뿐인 문항**도
    한 칸짜리 표가 되므로 축으로 쓰지 않는다.
  - 배점도, 응답이 나뉘는 선택형 문항도 없는 설문(서술형만 있는 설문 등)은 뜻 없는 총점 표 대신
    **응답 수(전체 × 전체)** 만 낸다.
- **`AI에게 추천 더 받기`** (선택, 2026-09-14) — 규칙 추천은 그대로 두고 AI 추천을 목록 끝에 덧붙인다.
  - 이유: 기본 3종은 예시일 뿐이고 실제로는 자유롭게 등록한 설문이 대부분이다. 규칙은 응답률 같은
    숫자 신호만 보므로 **문항끼리 짝짓는 추천을 만들지 못한다**(설문 16종 × 응답 상황 6가지 테스트에서
    문항 × 문항 추천 0개, 선택형 문항의 20%만 추천에 쓰임). 문항의 뜻을 봐야 하는 조합을 AI 가 보탠다.
  - 화면: 버튼을 누르면 `AI 추천` 배지를 단 추천이 **선택 해제 상태로** 붙고 미리보기 표가 함께 나온다.
    수정·미리보기는 규칙 추천과 같다. 서버가 걸러 낸 추천은 이유와 함께 보여 준다. 다시 받으면
    선택하지 않은 AI 추천만 바뀌고 선택한 것은 남는다. 조건·계정이 바뀌거나 STEP 1 에서 다시 시작하면
    기다리던 AI 답은 쓰지 않는다.
  - 키: STEP 4 와 같은 계정 AI 설정을 쓴다. 설정이 없거나 사용 중지면 버튼을 잠그고 *"이 계정의 AI가 미설정이거나
    사용 중지 상태입니다. AI 연동 설정을 확인해 주세요."* 로 안내한다. 공용 키로 대신 부르지 않는다.
  - API: `POST /analysis/recommend` — `/analysis/run` 과 같은 조건 + `existing`(지금 있는 기준, 중복 제거용).
    키 확인(없으면 412, 조회·AI 호출 0회) → 서버가 통계를 다시 셈 → AI 요청 → 답 검사 →
    `{ recommendations: [{ row, col, why, warn }], rejected: [{ 기준, 이유 }], warnings }`. 스트리밍 경로로 보낸다.
  - AI 입력 (`lib/analysis-recommend.js`): 설문 제목·설명·목적·대상, **선택형 문항**의 문장·종류·보기·배점·
    응답 분포, 응답 요약(건수, 나이·성별 기록 수, 기관·시군구·월 수), 이미 있는 기준, 쓸 수 있는 기준.
    **사람별 응답·서술형 문항 문장·서술형 답은 넣지 않는다.**
  - 서버 검사 규칙

    | 규칙 | 막는 것 |
    | --- | --- |
    | 기준 종류는 문항·연령대·총점 구간·성별·기관·시군구·처리 상태·조사 월·전체만, 표 엔진 검증 통과 | 만들 수 없는 기준 |
    | 문항 번호가 실제 있고 **선택형**이며, 이 조건에서 응답이 두 가지 이상 | 없는·서술형·한 칸짜리 문항 |
    | 이 조건에 값이 있는 기준만 (나이 기록 · 기관 2곳 이상 · 두 달 이상 등). 배점 없는 설문은 총점 구간 거절 | 빈 표 |
    | **총점·연령 경계값은 AI 가 정하지 못함** — AI 가 적으면 버리고 알림. 화면이 규칙의 참고 구간을 넣음 | 근거 없는 위험 기준점 |
    | 이미 있는 기준·AI 끼리 같은 조합 제거 (행·열을 바꾼 것도 같음), 행과 열이 같으면 제거 | 중복 |
    | 최대 5개 · 근거 220자 · 주의 160자 · 휴대전화·주민번호 형태 가림 · 근거에 통계에 없는 수치가 있으면 경고 | 과한 출력 · 유출 · 지어낸 수치 |
- 사용자는 원하는 추천을 **선택(복수 가능)**, 각 추천을 **수정**, 또는 **직접 추가**한다.
- 수정 화면의 **세부 설정은 행과 열을 각각 따로 낸다.** 행·열은 대칭이므로 설정도 대칭이다.
  `총점 구간` → 총점 경계값 / `연령대` → 연령 경계값 / `문항 응답별` → 문항 선택.
  - 화면 순서는 **행 → 행 세부 → 열 → 열 세부**다. 세부 설정을 그 축의 선택 상자 바로
    밑에 들여 붙여, 어느 축의 설정인지 자리로 드러낸다.
  - 축마다 항상 한 칸씩 나온다. 설정할 값이 없는 종류(성별·운영담당자별·시군구·조사 월·전체)
    도 그 자리에 "성별 은 추가로 설정할 값이 없습니다"를 보여 준다 —
    그래야 그 축이 무시된 게 아니라는 것이 화면에서 드러난다.
  - 행과 열의 설정은 **서로 독립**이다. `행=문항 2 × 열=문항 13` 처럼 같은 종류를
    양쪽에 두고 다른 값을 줄 수 있고, 총점 경계값도 행·열에 각각 다르게 줄 수 있다.
  - 문항은 번호가 아니라 **질문 문장 목록**에서 고른다.
  - `직접 기준 추가` 폼도 같은 구조를 쓴다(같은 `anDetailHtml`).
- 선택한 기준 하나당 STEP 3에 표가 하나씩 나온다.

#### 분석 기준 = { 행 차원, 열 차원, 셀 값 }

행과 열은 대칭이다. 각 차원은 아래 중 하나.

| 차원 종류 (`kind`) | 세부 설정 | 그룹 |
| --- | --- | --- |
| `all` | — | 1개 (요약) |
| `number_bins` | `field`(`score`\|`age`), `boundaries[]`(개수 자유), `labels?`, `unit?` | 경계 N개 → 구간 N+1개. 중복·미정렬 경계는 자동 정리(예: `[20,20,40]`→3구간). 경계값은 정수 가정(소수 경계는 라벨이 어색할 수 있음) |
| `attribute` | `field`(`gender`\|`institution`\|`sido`\|`sigungu`\|`status`) | 해당 값들 |
| `question` | `questionNo`, `labels?` | 그 문항의 응답 보기 |
| `month` | — | 기간 내 각 월 |

셀 값(`cells`): `count`(인원) · `pct`(행 대비 비율 %) · `mean`(그룹 평균 총점) 중 복수.

spec 예:
```json
{ "row": { "kind": "number_bins", "field": "age", "boundaries": [75, 85] },
  "col": { "kind": "question", "questionNo": "9" },
  "cells": ["count", "pct"] }
```

### STEP 3 · 통계 결과 도출
- ① 요약: N · 평균 · 중앙값 · 운영담당자 수
- ② 집계 표: STEP 2에서 선택한 기준마다 표 1개. 표마다 CSV.
- ③ 문항별 응답 분포: 문항별 "예"(또는 최고 점수 응답) 비율, 높은 순
- ④ 재현 정보: 처리 상태 · 사용 범위 · 제외(집계에서 빠진 레코드 수) · 가정 · 계산 방법 · 집계 기준
- 위험 구간이 아닌 총점 구간을 쓴 표에는 "참고 구간" 안내를 표 위에 붙인다.
- AI 개입 없음 (AI 추천으로 고른 기준도 계산은 코드가 한다).

### STEP 4 · 결과 분석 (선택)
AI가 STEP 3 통계를 근거로 **구조화된 분석(JSON)** 을 작성한다. 자유 서술이 아니다.
**참고자료는 선택사항**이다 — 없으면 통계 결과만으로 분석하고, 올리면 그 내용도 근거로 쓴다.

결과 = 조사 개요(설문·기간·기관 범위·처리 상태·응답 수) + 분석 항목 배열. 각 항목:

| 필드 | 규칙 |
| --- | --- |
| `분석_결과` | 하나의 결론 (한 문장) |
| `사용한_통계값` | STEP 3 수치를 그대로 인용 (재계산·가공 금지) |
| `참고자료_근거` | 참고자료의 인용 문장·조항과 어느 참고자료인지(`참고자료 1`). 없으면 `null`. **참고자료 없이 요청하면 항상 `null`** |
| `해석` | 실무적 의미. 인과 단정 금지. 참고자료가 없으면 지침·기준을 단정하지 않음 |
| `주의사항` | 이 결론을 읽을 때 감안할 한계 (5명 미만 칸은 결론 근거로 쓰지 않고 여기에 적음) |
| `근거_충분도` | `충분` \| `부분적` \| `불충분`. 참고자료가 없다는 이유만으로 낮추지 않음. `불충분`은 화면에 **판단 보류** |

#### 기관별 AI 키 (2026-09-14 결정)
- STEP 4 는 **수행기관별 AI API 키**로 AI 를 부른다. 키를 저장·교체하는 기능은 아직 없고,
  서버에 **키를 가져오는 자리 한 곳**(`resolveAnalysisAiCredential`)만 두었다. 지금은 항상
  "없음"이라 운영에서는 STEP 4 가 *"이 기관의 AI API 키가 설정되지 않아…"* 로 잠긴다.
  기관별 키 기능이 이 자리만 채우면 켜진다 (STEP 2 AI 추천도 같은 자리를 쓴다).
- **프로젝트 공용 키(`OPENAI_API_KEY` 등)로 대신 부르지 않는다** — 기관의 요청 비용이 프로젝트
  계정에 청구되기 때문이다. 키 원문은 브라우저·로그·AI 입력·응답 어디에도 넣지 않는다
  (`docs/AI_SETTINGS_CONTRACT.md`).
- 중앙·광역기관 계정이 누구의 키를 쓸지는 키 기능을 설계할 때 정한다. 지금은 로그인한 기관 기준.
- AI 요청 형식은 지금 OpenAI Responses 방식만 있다. 다른 제공사는 키 기능과 함께 붙인다(그전엔 501).
- AI 사용 기록은 남기지 않는다. `ai_generation_logs.action` 허용값이 DB 에 고정돼 있어 기록하려면 DB 변경이 필요하다.

#### API
- `GET /analysis/report/status` → `{ available, reason?, message? }`. 화면이 STEP 4 에 들어올 때 먼저 부른다.
- `POST /analysis/report` — 본문은 `/analysis/run` 과 같은 조건 + `specs` + `files[]`(`filename`, `fileBase64`).
  1. 참고자료 검사 (네트워크 없이 먼저) → 2. 기관 키 확인 — **없으면 412, 제출건 조회·AI 호출 0회** →
  3. 통계를 **서버가 다시 계산**(`computeAnalysis`, 화면이 보낸 숫자를 믿지 않음) · 응답 0건이면 400(AI 안 부름) →
  4. AI 요청 → 5. 답 검사 → `{ report, warnings, mode(statistics_only|with_references), referenceCount, model, generatedAt }`.
- AI 응답을 오래 기다리므로 `api.mjs` 의 **스트리밍 경로**(NDJSON 진행 신호)로 감싼다. 화면의 `apiRequest` 가 그대로 읽는다.

#### 참고자료 (`lib/reference-docs.js` · `lib/zip-read.js`)
받는 형식은 **글자가 텍스트로 들어 있는 파일**만이다. 최대 5개 · 합계 3.5MB.

| 파일 | 처리 |
| --- | --- |
| 텍스트 PDF | AI 에 파일 그대로 보냄 (AI 가 글자와 쪽 이미지를 함께 봄 — 표가 많은 지침에 유리) |
| DOCX · HWPX | 서버가 글자로 풀어 보냄. **표는 셀 단위로 살림**(`\| 칸 \| 칸 \|`). 외부 라이브러리 없이 Node 기본 zlib (압축 폭탄 상한) |
| 스캔한 PDF · 암호 PDF | 받지 않음 — 내용 스트림에 글자 쓰기 명령이 없으면 스캔본으로 판단 |
| PNG · JPG · 구형 HWP | 받지 않음 — 한글에서 PDF 또는 HWPX 로 저장하라고 안내 |

- DOCX·HWPX 에서 푼 글자는 **AI 로 보내기 전에 휴대전화·주민등록번호 형태를 가리고** 경고로 알린다
  (기관 대표번호·날짜·기관 이메일은 둔다). 푼 글자는 전체 60,000자까지만 쓰고 넘친 만큼 알린다.
- 거절 안내와 경고에는 **파일 이름**을 붙여 어느 파일인지 알 수 있게 한다. 파일 이름은 AI 에 보내지 않는다
  (AI 에는 `참고자료 1`, `참고자료 2` … 번호로만 보내고, 화면 목록에도 같은 번호를 붙인다).
- 참고자료에 실제 개인정보가 있다고 AI 가 판단하면(`blocked`) 분석하지 않고 422 로 알린다.

#### AI 입력과 답 검사 (`lib/analysis-report.js`)
- AI 입력: 조사 개요 · 요약 수치 · 표(기관코드는 기관 이름으로, 행 60 · 열 30 까지) · 문항 문장 · 문항별
  대표 응답. **사람별 응답·이름·생년월일은 넣지 않는다.** 수행기관 계정의 기관 범위는 본인 기관 이름.
- 답을 믿지 않고 서버가 검사한다.
  - 6개 필드 · 값 · 길이 검사. 필수 내용이 빠진 항목은 빼고, 항목은 최대 10개.
  - **인용 수치 대조** — `분석_결과`·`사용한_통계값`의 숫자가 통계 결과에 없으면 `검증.찾지_못한_수치` 를 붙이고
    `불충분`(판단 보류)으로 내린다. AI 가 매긴 값은 `검증.원래_근거_충분도` 에 남긴다.
  - 참고자료 없이 요청했는데 `참고자료_근거` 를 채워 오면 지우고 경고한다.
  - 답에 휴대전화·주민번호 형태가 있으면 가리고 경고한다.
  - 조사 개요는 AI 가 쓴 것을 버리고 서버가 조건으로 만든다.

#### 화면
- 들어오면 사용 가능 여부부터 확인 → 키 없음이면 안내만, 있으면 참고자료 올리기(선택) + `결과 분석 요청`.
- 올리지 않은 파일(형식·개수·크기)은 이유와 함께 목록 아래에 남긴다. 스캔본 여부 같은 내용 검사는 서버 몫이다.
- 결과: 조사 개요 · 서버 검사 결과(경고) · 항목별 카드(근거 충분도 배지, ⚠ 수치 확인 필요) · `JSON 복사` · `JSON 내려받기`.
- **STEP 3 통계가 바뀌면 이전 분석은 버린다** — STEP 2 기준을 다시 승인하거나, STEP 1 에서 다시 시작하거나,
  조회 조건이 바뀌거나, 새로고침 없이 다른 기관으로 로그인하면 결과를 비우고 **기다리던 요청의 답이 늦게 와도 쓰지 않는다.**
  참고자료는 기준을 다시 승인할 때는 남기고, 조건·계정이 바뀌면 비운다.
- STEP 3 응답이 0건이면 요청 버튼을 잠근다.
